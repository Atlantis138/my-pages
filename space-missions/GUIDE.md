# 深空航迹 · 开发规范

这份文件约定图集里的任务页怎么写：目录怎么放、脚本和引擎之间的接口、页面骨架、主题、文字与数字的写法、数据怎么来。新增任务或改动共享代码之前先读一遍。

## 1. 原则

1. **不构建。** 页面就是仓库里的文件：改完刷新即可。脚本用 ES 模块，数据用 `fetch` 读 JSON。
2. **一套引擎，各自成册。** 相机、时间轴、读数、快捷键这些“怎么看图”的东西全在 `shared/`，所有任务一致。任务自己的数据、文字、主题、专题版块都在 `missions/<id>/` 里，互不引用。
3. **轨迹必须有出处。** 探测器的轨迹来自实测星历或官方轨道解，处理脚本和与史料的对照放在该任务的 `recon/` 里。页面上凡是“本图算出”的数值与史料不一致，就两个都写。
4. **先在任务里写，第二次用到再提到 `shared/`。** 只有一个任务用的组件（样式、绘图函数、图表）留在任务文件夹；第二个任务也要用时，再挪进 `shared/` 并让两边都引用。

任务 id 用小写字母和数字（`cassini`、`isee3`），它同时是文件夹名、主题类名 `.theme-<id>` 和 `<html data-mission>` 的值。

## 3. 新增一个任务

1. **准备数据。** 在 `missions/<id>/recon/` 里写脚本，把轨迹处理成页面要的 JSON（见 §8），并写好 `recon/README.md`。
2. **复制模板。** `cp -r missions/_template missions/<id>`，把三处 `template` 换成 `<id>`：`index.html` 的 `class="theme-…"` 和 `data-mission`、`theme.css` 的选择器。
3. **定主题。** 在 `theme.css` 里换一套纸色、笔色和一对字体（§6），`index.html` 的字体链接同步改。
4. **写任务脚本。** 按 §4 在 `mission.js` 里换上真实数据：阶段、事件、机位、渲染、读数。
5. **写文字。** 按 §5 的骨架写页首、图例、每个阶段一章的日志、专题版块、「关于这张图」和资料来源。
6. **登记。** 在 `missions/registry.js` 按发射时间加一项；在 `tools/thumbs.mjs` 的 `THUMBS` 里加一项并运行，生成 `thumb.svg`。
7. **检查。** 过一遍 §9，再更新仓库根目录 `index.html` 的卡片文字和 `README.md`。

## 4. 任务脚本

`mission.js` 从上到下的顺序固定为：时钟 → 外框与数据 → 轨迹与星历 → 阶段 → 事件 → 渲染 → 读数 → 启动。`_template/mission.js` 是带注释的最小例子。

### 4.1 时间与单位

- 页面内部的时间 `t` 一律是**距任务历元的天数（UT）**。`const clock = makeClock(Date.UTC(年, 月-1, 日), 历元的儒略日)`，从中取 `T('2004-07-01T02:37')`（字符串 → t）、`isoDate`、`utc`、`jd` 等。
- 每个坐标系自己定“1 个场景单位 = 多少 km”，写在该坐标系的 `unit` 里，比例尺据此自动生成。**日心黄道坐标系全站统一为 1 单位 = 0.1 AU**（`UH`、`HELIO_FRAME`）。
- z 轴朝上，基准面是 z = 0（黄道面、环平面……）。

### 4.2 `createPlayer(cfg)`

| 字段 | 说明 |
|---|---|
| `clock` | `makeClock` 的返回值 |
| `segments` | 阶段列表，见下 |
| `events` | 事件列表，见下 |
| `frames` | `{ 代号: { en, zh, sub, unit, minDist, maxDist, render(g, t) } }`。`render` 画完一帧并**返回探测器的位置**（“跟随”要用） |
| `readouts(g, t)` | 返回 `{ rows: [[名称, 数值], …], src: '数据来源' }` |
| `startT` | 没有 `#t=` 时打开页面看到的时刻，选全程最有看头的一刻 |
| `playMs` | 1× 速度下播完全程的毫秒数（约 2 分钟） |
| `focus` | 可选。`[[时刻, 宽度（天）, 1× 时每秒最多走几天], …]`，播放到近距飞越时放慢；这些时刻附近同时显示时分秒 |
| `marks` | 可选。时间轴上排的细刻度 `{ t, color: 令牌名, d, x }`，用于“每一次飞越” |
| `jumps` | 可选。`{ 名字: { t, then?(t) } }`，供 HTML 里的 `data-jump="名字"` 按钮使用 |
| `timeShown(t, g)` | 可选。除 `focus` 外还有哪些时候要显示时分秒 |
| `liveNote(g, t)` | 可选。没有事件注记时，此刻要不要说点什么，返回 `{ d, x }` 或 `null` |
| `onTime(t, g)` | 可选。每画一帧调用一次，用来同步页面上别的图表 |

返回的对象：`state`（`t`、`u`）、`cam`、`segment`、`lock`、`setT(字符串或 t)`、`jumpT(t, then)`、`jumpSeg(i)`、`jump(名字)`、`lockOn(目标, 视角)`、`reveal()`（把图滚回视野）、`invalidate()`。页面把它挂在 `window.__mission` 上，冒烟测试和调试都靠它。

**阶段** `{ id, name, short, yr, t0, t1, w, frame, show, cam(t) }`
`id` 与 HTML 里章节的 `data-seg` 对应；`name` 显示在图的右上角，`short`、`yr` 显示在时间轴上（`short` 不超过四个字）；`w` 是时间轴上的相对宽度，按“有多少可看”而不是按时长分配；`show` 是点“在图上看这一段”或按数字键时跳到的时刻；`cam(t)` 返回机位 `{ tx, ty, tz, dist, az, el }`，按宽幅画面取景，窄屏会自动后退。近距飞越的推近用 `closeUp(远景, t, [{ t, a, b, cam }])`。阶段编号 `01、02…` 由引擎按顺序生成。

**事件** `{ t, win, d, x, at?, key? }`
`t` 注记出现的时刻，`win` 停留的天数，`d` 日期文字，`x` 一句话说明（不加句号），`at` 是事件按钮和刻度跳到的时刻（默认同 `t`），`key: 1` 标记重要事件（刻度更高）。说明里的数值尽量由数据算出，不要手抄。

**镜头锁定** `player.lockOn({ id, label, pos: t => 场景坐标, maxDps?: (t, rate) => 天/秒 }, { dist, el })`，用于“把镜头钉在一颗运动的天体上看飞越”。

### 4.3 画图（`shared/scene.js`）

任务的 `render` 只调用下面这些基元，颜色只取 `C.<令牌>`，不写死色值。

| 用途 | 函数 |
|---|---|
| 坐标纸 | `grid({ polar, z0, fine })`：格距随缩放自动变化。以中心天体为原点的坐标系用 `polar: true`，旋转坐标系用方格 |
| 线 | `poly(Float64Array, i0, i1, 颜色, 线宽, 透明度, { dash, flat, af })`、`seg3(a, b, …)`、`arrow(a, b, …)`、`dropLine(p, 颜色, z0)` |
| 天体 | `body(中心, 真实半径, 太阳方向, 填色, 描边, 最小像素)`、`sun(p, 半径, 最小像素)`、`dot2(p, r, 填色, 描边)`、`shadedDisk`（自己做变形时用） |
| 探测器 | `craftMark(p, 名字, 标签放左边?)` |
| 标签 | `placeTag(id, p, 文字, 类名, dx, dy)`：每帧调用，没调用到的自动隐藏 |
| 日心系 | `equinoxArrow()` |
| 相机 | `cam`、`viewR()`、`lerpCam`、`lerpZoom`、`at(p, {…})`、`closeUp`、`env` |
| 只读状态 | `ctx`、`gAlpha`、`isDark`、`B`、`PO`、`focal`、`proj(x, y, z)`（需要直接操作画布时） |

图面的统一画法：

- 探测器：`craftMark`，笔色。已飞过的路径笔色 2.2 px；还没飞到的 `ink-2` 1.1 px、透明度约 0.45；更早的圈数笔色 1 px、透明度 0.3。
- 天体**拉近后按真实大小**，远景不小于 3—5 px；背阳面按真实的太阳方向涂暗。先画天体再画轨迹。
- 太阳和它的方向用 `gold`，地球用 `blue`；其余天体的颜色由任务自己定义令牌，并在图例里交代。
- 离开基准面的东西（探测器、彗星）用 `dropLine` 垂到基准面上。
- 标签用中文（类名带 `zh`），探测器名、编号和拉丁字母缩写用等宽体。

### 4.4 其他模块

- 飞行器示意：`createSketch(canvas, draw(c, w, h, now), live)`（`shared/sketch.js`）。只在看得见时才画，换主题会自动重画。
- 监听 `document` 上的 `tokenschange` 事件，可在主题切换后重画自己的图表。

## 5. 页面骨架

`index.html` 的 `<head>` 照抄模板（`theme.js` 必须在样式表之前、同步载入）。`<body>` 的顺序固定：

1. `main.bench`
   - `header.mast`：`p.eyebrow`（`机构 / 机构 · 任务代号 · <b>起—止年份</b>`，全大写拉丁字母）、`h1`（`span.h1-id` 拉丁代号 + `span.h1-zh` 中文）、`p.lede`（三四句话讲清去了哪、怎么去的、为什么值得看）。页首导航由脚本插入。
   - `section.plot#plot`：留空，外框由引擎生成；`aria-label` 写“××三维轨迹图”。
   - `section.log`：先是 `div.legend`（标题固定为“怎么读这张图”：线型与标记的图例、一段讲坐标系的话；操作说明和快捷键由引擎接在后面），然后**每个阶段一篇** `article.ch[data-seg]`：`div.ch-head`（编号 + 日期范围）、`h2`、一到三段正文、`dl`（两到四项关键数据）、`div.gotos`（“在图上看这一段 →”以及可选的 `button.goto.sm[data-jump]`，文字以“看”开头）。
2. 专题版块 `section.section`，每个以 `div.sec-head`（`span.kicker` 英文小标题 + `h2` + 导语）开头，顺序为：
   - **BY THE NUMBERS**：`div.figures`（`data-cols="4"` 或 `"6"`），4、6 或 8 个数字；
   - 任务特有的专题（卡西尼的轨道剖面、卫星、发现）；
   - **THE SPACECRAFT**：`div.craft`（`figure.craft-fig` 示意图 + `dl.spec` 规格表，可接 `div.inst` 仪器清单）；
   - **LEGACY**：`div.heirs`。
3. `footer.foot`：左栏“关于这张图”（数据来源、处理方法、与史料的对照、做了哪些简化，末尾给出 `recon/` 的链接），右栏“资料来源”（`ul.sources`，格式 `机构或作者 · 标题`）。

不写内联样式；需要新样式就加类，放进任务的 `theme.css`。

## 6. 主题

每个任务一套主题，写在 `theme.css` 的 `.theme-<id>` 上，深色写在 `[data-theme="dark"].theme-<id>, [data-theme="dark"] .theme-<id>` 上（这样首页的卡片也能直接用）。必须给全下列令牌：

| 令牌 | 用途 |
|---|---|
| `--paper` `--sheet` `--veil` | 页面底色、图纸底色、盖在图上的半透明底（`--sheet` 加 0.8 透明度） |
| `--ink` `--ink-2` `--rule` `--grid` | 文字与粗线、次要文字、分隔线、坐标纸 |
| `--pen` `--pen-wash` | 这个任务的笔色：探测器、当前阶段、强调；`--pen-wash` 是它的 12—16% 透明度 |
| `--gold` `--blue` | 太阳与巨行星、地球 |
| `--f-display` `--fw-display` `--f-mono` | 展示字体（大标题、日期、大数字）及其字重、等宽字体 |

- 各任务用不同的纸色和笔色，一眼能分清；正文字体 `--f-text`（思源宋体）全站统一，不要改。
- 任务独有的颜色（如 `--titan`）在同一处定义，并在 `mountPlot({ tokens: [...] })` 里登记，画布才读得到；需要同名的标签颜色时加一条 `.theme-<id> .tag.<名字>`。
- 所有颜色都要有深浅两个值。会用作文字的颜色（`--pen`、`--ink-2`、`--gold`、`--blue`，以及任务自己的标签颜色）在 `--sheet` 上的对比度不低于 4.5:1；只用来画点和线的颜色不低于 3:1 即可，像卡西尼那样分成 `--titan`（图形）和 `--titan-ink`（文字）两个。
- 展示字体选窄体、带表格数字的无衬线体；字体在任务页 `<head>` 和 `registry.js` 的 `gfonts` 里各写一次。

## 7. 文字与数字

- **语气**：平实的说明文。先说事实，再说为什么；不用感叹号，不堆形容词。专有名词第一次出现时给出中文和原文或编号，如“泰坦（土卫六）”。
- **日期**：`1997-10-15`；带时刻写 `2004-07-01 02:37 UT`（一律 UT，不写 UTC、GMT）。正文里可以写“1997 年 10 月 15 日”。年份范围用一字线 `1997—2017`，时间轴上的缩写用短横 `1997–98`。
- **数字**：千位用逗号（`7,862 km`）；10 万 km 起用“万 km”（`15.8 万 km`、`979 万 km`），一律通过 `fmtKm`；行星际距离用 AU 保留三位小数；速度 `km/s`；光行时用 `fmtLight`。数字与单位、中文与拉丁字母或数字之间留一个空格。
- **距离说清基准**：“距表面”“距云顶”“距土星中心”“距月面”，不写含糊的“距离”。
- **用词**：借力（不写“引力弹弓”）、飞越、近土点 / 近地点、定向飞越、探测器（指飞行器）、“卡西尼号”带“号”字。
- **标点**：中文全角标点；并列的短语用 `·` 分隔（图上的注记、`dl` 里的数值）。
- **本图与史料**：两者不同就都写，“623 km（本图 603 km）”，并在「关于这张图」里解释差别从哪来。

## 8. 数据与 `recon/`

- 页面载入的数据放 `missions/<id>/data/`，JSON，单个任务合计不超过 1 MB。轨迹要抽稀：按“与真实轨迹的偏差不超过到最近天体距离的千分之几”取舍，近距飞越处加密。
- 轨迹的两种现成格式（`shared/track.js`）：行式 `[t, x, y, z, (速度)]`（`unpackRows`），或秒 / km 的差分编码 `{ t0, p0, dt, dp }`（`unpackDelta`）。
- `recon/` 里放处理脚本和体积不大的原始数据；下载缓存（`cache/`）和中间文件不入库（写进 `.gitignore`）。
- `recon/README.md` 必须有三部分：**怎么运行**（按顺序列出命令）、**数据来源与方法**、**检验**（一张“本数据 / 史料”的对照表）。
- 页面用来画天体的近似星历在 `shared/astro.js`。如果 `recon/` 的脚本需要与页面用同一个星历（比如按页面里的月球位置导出相对量），就在 `recon/` 里放一份 Python 镜像，并在两边的注释里互相指明。

## 9. 提交前检查

1. `node tools/smoke.mjs` 全部通过。
2. 浅色、深色各看一遍；手机宽度（390 px）看一遍；全程播放一遍，机位衔接没有跳变。
3. 每个 `data-jump` 按钮、每个阶段的“在图上看这一段”都点一遍。
4. 带 `#t=…` 的链接能直接打开到那个时刻。
5. 键盘能完成全部操作：`Tab` 到时间轴后方向键可拖动，快捷键有效。
6. 「关于这张图」里写的数值与 `recon/README.md` 的检验表一致。

提交说明以 `space-missions:` 开头，说明改了哪个任务或哪部分共享代码。改动 `shared/` 时，所有任务页都要重新检查一遍。
