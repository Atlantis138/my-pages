# 完整介绍页制作规范

一句话：**用这种风格，做一页介绍这种风格的网页。** 读者看完应当知道：它长什么样、为什么这样、怎么做出来、什么时候该用。

规范只管底线，不管审美。版式、叙事方式、交互形式都由作者按风格自由发挥。

## 必须做到

1. **自成一体。** 页面只属于这一种风格：不链接其他风格页，不做跨风格对比表，也不出现图鉴编号之类的外部信息。唯一的出口是一个返回图鉴的按钮（`../../#s-<id>`），放在始终容易找到的位置，并用该风格自己的样子画出来。
2. **一键复原。** 只要页面有会被改变的状态（明暗、参数、组件开关、输入），就提供一个随时可见的复原按钮。它要清掉本页存的 localStorage 键，把表单控件改回默认值（否则浏览器刷新后会自动恢复它们），然后重新载入，并给出一句反馈。
3. **每一块都有信息增量。** 每个分区都要让读者多知道一点或多感受到一点。空泛的赞美、换个说法的重复、为凑版面而放的卡片都删掉。能演示的就演示，不要只靠描述。
4. **用风格本身说话。** 配色、字体、形状、质感、动效和组件都按这种风格来做，连按钮、提示、页脚也不例外。风格的缺点也照实呈现，最好同时给出改良的做法。
5. **事实可核。** 年份、人物、规范数值写之前要查证，拿不准的就写得模糊些或者不写。页面上的近似实现（比如简化的算法）要注明。

## 技术底线

- 文件只放在 `styles/<id>/` 里，不依赖其他风格的文件夹，也不要新建以 `_` 开头的文件或文件夹（GitHub Pages 的 Jekyll 会把它们丢掉）。
- 没有构建步骤，原生 HTML、CSS、JS 即可，可以用 ES 模块。外部资源只用 Google Fonts，或者 CDN 上锁定版本号的库。
- 360px 宽时不出现横向滚动。键盘可以操作，焦点环清晰可见。尊重 `prefers-reduced-motion`。
- 正文对比度不低于 4.5 : 1。风格本身的低对比只能用在装饰和演示上，不能用在正文上。
- localStorage 的读写都包在 try/catch 里，键名加上风格前缀（如 `md-`、`nm-`）。
- 如果这种风格有合理的深色版本，就跟随系统并提供切换；风格本身只有一种明暗（如复古终端）时可以不做。

## 内容分区（参考，不是模板）

| 分区 | 回答的问题 | 例子 |
|---|---|---|
| 首屏 | 它长什么样？ | 第一眼就是最典型的样子，最好有一个能上手的招牌交互：Material 的动态配色，新拟态的光源旋钮 |
| 原理 | 它靠什么成立？ | 用最少的话讲清核心机制，配一张拆解图 |
| 来历 | 它从哪来、在回应什么？ | 时间线、关键人物和作品 |
| 视觉语言 | 它的规则是什么？ | 色彩、字体、形状、质感、动效、版式，只讲这种风格真正有规则的部分 |
| 动手 | 用起来是什么感觉？ | 组件、生成器、实验室、小游戏，让读者自己摸索 |
| 好与坏 | 什么时候用、容易错在哪？ | 适合 / 慎用 / 常见错误，最好做成错误与正确的对照 |
| 实现 | 怎么写？ | 关键 CSS 与容易踩的坑 |

**按风格调配比重。** 规范多的风格（Material、瑞士风格）可以把「视觉语言」讲得很深。偏艺术的风格（蒸汽波、垃圾摇滚）这一节可以很短，把篇幅留给首屏和「动手」，用氛围、作品和可玩的交互让读者去感受。内容少不等于页面单薄。

分区可以合并、拆分、改名、重排，也可以用非常规的形式来呈现，比如整页是一张海报、一个终端或一局游戏，只要上面四个问题都得到了回答。

## 收尾检查

- [ ] 全页只有一个指向图鉴的链接
- [ ] 复原按钮能把所有状态都还原
- [ ] 删掉任何一节，读者都会少知道点什么
- [ ] 手机宽度、深色模式、纯键盘、减少动效下都正常，控制台没有报错
- [ ] 在 `styles/registry.js` 里给该风格加上 `page: true`
